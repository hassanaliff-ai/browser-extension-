# ExtSecure 0.8.8 verification: automation and control effectiveness

Implemented configurable rules with priority, minimum risk, scan type, automatic case creation, investigator/reviewer selection, and a 1–720-hour unresolved-case deadline. Assignment and review notifications are durable in-app notices. The API sweeps every 60 seconds and also supports an audited manual check. Escalations use case revisions and unique notice identifiers; a resolved case is not escalated, and reopening starts a new deadline. Rules start disabled and are restricted to administrators. Managers see only their own notices. No automation grants website access or changes risk evidence.

The evaluator supports 7/30/90/365-day windows, median/p95 response times with sample counts, exception suppression/whitelist activity, notification delivery outcomes, repeated target/device detections and evidence-based control assessments. Latest reviews and independent labels replace previous labels for metrics without deleting history. Unknown results and unverified labels remain unassessed; absent reviews yield no effectiveness percentage. Browser navigation observations are authenticated client reports, not independent enforcement proof; URL fingerprints are retained rather than full destinations. Telemetry is best-effort and does not weaken blocking. Navigation observations follow the existing explicit retention cleanup.

- 27 new backend feature tests passed: authenticated route grants, disabled defaults, rule precedence, automatic cases/notices, exception suppression, strict validation, stale revisions, deadline behavior, reopening, manual assignment preservation, private inboxes, inactive investigators, mounted API lifecycle, assessment references, corrected labels, empty metrics, response-time calculations, period boundaries, telemetry deduplication/privacy and retention.
- 196 backend regression tests passed across governance, roles, scans, approvals, schema compatibility, notifications, main API and extension integration. The 35 governance tests were also rerun after the retention change.
- 196 extension tests passed, including seven new tests for route restrictions, form serialization, evidence filtering, disabled submission without evidence, private/deduplicated telemetry and monitoring outages.
- Eight isolated headless Chrome layout checks passed for both new screens in English/Arabic and light/dark at desktop/mobile widths. Browser interactions verified rule creation, administrator-only escalation choices, acknowledgement, opening an incident, evidence filtering/submission, changing reporting period and manager scoping. Real UI assets were used with synthetic data and a worker double; the user's authenticated browser profile was not exercised.
- Extension ZIP CRC and source hashes verified: 31 runtime assets, version 0.8.8.

No new dependencies or Chrome permissions. Installation uses an additive schema initializer and preserves private account/service configuration. Reload the installed extension and reopen its console after updating. The existing external email/webhook alert configuration is separate from in-app workflow notices.
